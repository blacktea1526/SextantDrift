# ADR-004: 将语义不变量 (Invariants) 匹配深度限定在同函数/作用域 AST 范围

## Status
Accepted

## Date
2026-09-16

## Context
语义不变量（Semantic Invariants，如“落库必须在调用外部 AI 前先执行”、“UI 表现层严禁直连数据库驱动”）是 SextantDrift 区别于传统粗粒度架构检查工具的核心护城河。

然而在第一版尝试中，项目踩下了沉重的**陷阱 3（试图用纯静态推断猜测异步执行时序，引发假阳性噩梦）**：
- 现代 TypeScript 代码充斥着 `Promise.all`、事件总线发布订阅（Event Emitter）、依赖注入（DI）、回调流水线与异步微任务；
- 任何试图仅凭静态代码推断多文件、跨函数异步事件实际发生时序的尝试，在理论上等价于停机问题，必然伴随大量的**假阳性（误报）与假阴性（漏报）**；
- 在开发者工具与 CI 门禁领域，**误报等于自杀**。一次将合规重构代码误判为致命违规的虚假报警，就会彻底动摇工程团队对工具的信任。

因此，必须在静态分析阶段明确一条不可逾越的**形式化确定性边界（Determinism Boundary）**：只做确定性级别达到 9~10 的确凿语法判定，坚决不越界推测不可靠的运行时因果。

## Decision
我们决定将 Phase 2 的语义不变量（Invariants）规则引擎的匹配深度**严格限定在同函数/同步作用域内的 AST 语句拓扑与文件级 Import 拦截**：

具体规则匹配范式：
1. **时序先验规则 (`must_precede`)**：
   - **分析边界**：严格限制在**同一个函数体、方法体或同步块作用域**（`ts.Block`）内部；
   - **判定逻辑**：遍历当前块级作用域的直属语句列表（`statements`），断言目标语句节点（如 `llmService.call`）的前置语句序列中，必须确凿存在前提语句节点（如 `db.save` / `repo.create`）；
   - **确定性保证**：同一函数体内的语句线性执行次序具备 100% 确定性，不跨越函数间调用流（No Inter-procedural Guesswork）。
2. **跨层违禁导入规则 (`forbid_import`)**：
   - **分析边界**：文件顶级 `ImportDeclaration` 与 `ExportDeclaration`；
   - **判定逻辑**：严禁特定文件范围（如 `src/views/**`）包含指向被禁止模块（如 `@prisma/client`, `src/repositories/**`）的物理导入。
3. **因果时序延后律**：
   - 跨模块、跨微服务的异步真实执行因果流，**明确留待 Phase 5 依托动态测试 Trace（Dynamic Test Tracing）解决**，不在静态阶段盲目猜测。

## Alternatives Considered

### 1. 跨函数过程间数据流分析 (Inter-procedural Dataflow / Taint Analysis)
- **优点**：能够理论上追踪调用链传递（如函数 A 调用函数 B，B 负责落库）。
- **缺点**：算法复杂度呈指数级上升，在 10 万行项目中分析耗时将由毫秒级暴增至数分钟甚至数小时，直接摧毁“5 秒原则”；且在 JavaScript 高度动态的闭包、函数传递与中间件中，极易产生高达 30%~50% 的误报。
- **拒绝理由**：严重违反“戒律 2（严禁静态推断异步时序，杜绝假阳性）”。宁可缩小覆盖范围确保 100% 准确，绝不提供充满噪音的猜测性告警。

### 2. 正则表达式模式匹配 (Regex Pattern Matching)
- **优点**：实现成本极低，仅需搜索关键词。
- **缺点**：完全丢失语法上下文，无法区分注释、字符串字面量与真实执行代码；无法判断语句间的从属作用域关系。
- **拒绝理由**：第一版已验证为失败的技术路线，必须彻底弃用。

## Consequences

### 正向收益
- **100% 零误报底线**：在既定匹配深度内，每一条告警均具备确凿的 AST 节点行号与语法位置证据，杜绝任何概率式猜测；
- **毫秒级极速执行**：仅需在单遍 AST 遍历过程中针对匹配函数的语句列表进行单向扫描，执行开销 < 5ms，完全符合 5 秒原则；
- **心智模型极度清晰**：规则意图对人类与 AI Agent 均高度透明直观，开发者一眼即可看懂并迅速重构通过。

### 妥协与代价
- 无法捕获被拆分到多层私有辅助函数（Private Helper Functions）深处的先验动作。建议工程团队将关键业务事务（落库与外部调用）保持在用例服务（Use Case / Service）的顶层主函数内显式编排，这也同时契合清晰架构（Clean Architecture）的整洁原则。
